# دليل الإعداد (Supabase + Vercel + GitHub)

الترتيب: **1) GitHub ← 2) Supabase ← 3) Vercel ← 4) أول مستخدم**. المدة المتوقعة: نحو 20 دقيقة.

## 1) GitHub
1. أنشئ مستودعاً (عاماً أو خاصاً) وارفع **محتويات** هذا المجلد إلى جذره: يجب أن يظهر `web/` و`supabase/` و`scripts/` و`vercel.json` و`.github/` مباشرة.
   - رفع المجلدات المخفية (`.github`) من المتصفح يفشل أحياناً؛ تأكد من ظهوره، أو استخدم GitHub Desktop أو `git push`.
2. يشغّل `.github/workflows/ci.yml` تلقائياً: اختبارات المنطق، واختبارات قاعدة البيانات (RLS) على Postgres حقيقي، واختبار المتصفح.

## 2) Supabase
1. أنشئ مشروعاً جديداً على supabase.com واختر أقرب منطقة.
2. من **SQL Editor** ← New query، الصق كامل محتوى `supabase/migrations/0001_schema.sql` ← Run. يجب أن تظهر "Success".
3. من **Authentication ← Providers**: تأكد أن Email مفعّل. للتجربة السريعة يمكنك إيقاف "Confirm email"؛ وللعمل الفعلي اتركه مفعلاً.
4. من **Project Settings ← API** انسخ:
   - **Project URL**
   - مفتاح **anon / publishable** (المفتاح العام فقط).
   - **لا تنسخ أبداً** `service_role` أو `secret`؛ سكربت البناء يرفضهما.
5. بعد أن تحصل على رابط Vercel (الخطوة التالية) ارجع إلى **Authentication ← URL Configuration** وضع الرابط في **Site URL**.

## 3) Vercel
1. Add New ← Project ← اختر المستودع.
2. اضبط:
   - Framework Preset: **Other**
   - Build Command: `node scripts/build.mjs` (موجود في `vercel.json`)
   - Output Directory: `dist`
3. **Environment Variables** أضف:
   - `SUPABASE_URL` = Project URL
   - `SUPABASE_ANON_KEY` = المفتاح العام
   - `SUPABASE_SERVICE_ROLE_KEY` = مفتاح **service_role** (Supabase ← Project Settings ← API ← service_role). **سرّي:** يُستخدم فقط في الدالة `api/create-user.js` على خادم Vercel ليتمكن المدير من إنشاء مستخدمين؛ لا تضعه في أي ملف داخل `web/` ولا ترفعه إلى GitHub. بعد إضافته اعمل Redeploy.
4. Deploy. كل push على `main` ينشر تلقائياً، وكل Pull Request يحصل على رابط معاينة (Preview) مستقل. أضف روابط المعاينة إلى Redirect URLs في Supabase إن احتجت تسجيل الدخول منها.

## 4) أول استخدام
1. افتح موقعك ← **إنشاء حساب** (كل شخص ينشئ حسابه بنفسه أولاً).
2. أنشئ مشروعاً؛ تصبح تلقائياً **admin**.
3. من صفحة **الفريق** أضف زملاءك: اكتب البريد والصلاحية (`viewer` قراءة / `editor` تعديل / `admin`) وكلمة مرور افتراضية (8 أحرف على الأقل، أو اضغط **توليد**) ثم **إنشاء وإضافة**. أعطِ المستخدم البريد وكلمة المرور؛ سيُطلب منه اختيار كلمة مرور خاصة عند أول دخول، ويمكنه تغييرها لاحقاً بالضغط على بريده في أعلى الصفحة. إن كان البريد مسجلاً مسبقاً يُضاف إلى المشروع دون تغيير كلمة مروره.
4. من صفحة **استيراد** ارفع ملف Excel، ثم اتبع الصفحات بالترتيب.

## كيف يعمل التعاون
- كل عنصر (اختبار، مجموعة بحث، رمز...) سجل مستقل بنسخة (version). تعديلان على عنصرين مختلفين لا يتصادمان أبداً.
- عند تعديل العنصر نفسه في وقت واحد: يُدمج الحقلان المختلفان تلقائياً؛ وإن عُدّل الحقل نفسه يظهر تنبيه "تعارض دُمج" ويبقى أحد القيمتين، والأخرى في سجل التدقيق.
- التحديثات تصل للجميع لحظياً (Supabase Realtime)، ويظهر في الأعلى من متصل الآن.
- الصلاحيات تُفرض في قاعدة البيانات (RLS)، فلا يمكن لمشاهد (viewer) التعديل حتى لو عبث بالمتصفح.
- **سجل التدقيق** (من عدّل ماذا ومتى) يُكتب بواسطة trigger في قاعدة البيانات لا يستطيع العميل تزويره. و**النسخ المسمّاة** تحفظ حالة المشروع كاملة ويمكن استرجاعها.

## التطوير المحلي بدون Supabase
```
node scripts/devserver.mjs          # خادم محاكٍ في الذاكرة على :8787
npx http-server web -p 8765         # أو أي خادم ثابت
```
ثم عدّل `web/config.js` مؤقتاً إلى `{ backend: "dev", devServer: "http://localhost:8787" }` (لا ترفع هذا التعديل).

## نسخ احتياطي
Supabase (الخطة المجانية) لا يتضمن نسخاً احتياطية يومية قابلة للاسترجاع. استخدم **النسخ المسمّاة** داخل المنصة، ويمكنك تصدير `project.json` من صفحة التصدير وحفظه في GitHub.
